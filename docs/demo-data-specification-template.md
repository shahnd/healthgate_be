## 보여줄 내용

> 시연에서 보여주려는 기능과 그 기능이 필요한 이유를 간단히 설명합니다. 모든 API를 나열하지 말고, 데이터가 준비되어야 확인할 수 있는 동작과 결과를 중심으로 작성합니다.
>
> 예: 관리자가 부서별 직원 목록을 조회하고 이름으로 직원을 검색하는 기능을 보여준다.



## 시연 흐름

> 로그인부터 결과 확인까지 실제로 조작할 순서대로 작성합니다. 사용할 화면, 검색 조건, 선택할 데이터, 입력할 값과 기대 결과가 드러나면 됩니다. 독립된 흐름이 여러 개라면 번호나 소제목으로 구분합니다.
>
> 예:
> 1. 관리자 계정으로 로그인하여 직원 목록을 연다.
> 2. 개발팀을 선택하여 소속 직원만 표시되는지 확인한다.
> 3. 이름에 `김`을 입력하여 검색 결과를 확인한다.



## 미리 필요한 데이터

> 시연 전에 존재해야 하는 데이터를 적습니다. 개수, 구분에 필요한 주요 값과 상태, 다른 데이터와의 관계를 포함합니다. 일부 데이터가 시연 도중 생성된다면 미리 준비할 데이터와 구분합니다. 정렬이나 페이지네이션을 보여주려면 화면에 충분한 개수도 명시합니다.
>
> 예:
> - 개발팀 직원 5명: 이름 검색 결과를 보여주기 위해 `김`씨 직원 2명을 포함한다.
> - 인사팀 직원 2명: 부서 필터가 다른 부서 직원을 제외하는지 확인하는 데 사용한다.
> - 퇴사 직원 1명: 재직 상태 필터의 차이를 보여주는 데 사용한다.



## 계정과 권한

> 공통 시연 계정을 사용할 수 있는지, 특정 권한이나 소속이 필요한지 적습니다. 로그인한 직원과 업무 데이터의 관계에 따라 결과가 달라진다면 그 관계도 설명합니다. 비밀번호 같은 비밀 값은 이 문서에 기록하지 않습니다.
>
> 예: 공지 등록에는 관리자 계정이 필요하고 공지 조회에는 일반 직원 계정을 사용한다. 두 계정 모두 기존 공통 시딩 계정을 사용한다.



## 날짜 조건

> 연도, 유효 기간, 마감 여부처럼 시연 결과에 영향을 주는 날짜만 작성합니다. 결과를 고정해야 하는지, 시연일을 기준으로 계산해야 하는지도 구분합니다. 날짜 조건이 없다면 없다고 적습니다.
>
> 예: 2026년도 건강검진 대상자와 미검진자를 조회한다. 시연일과 관계없이 결과가 같도록 대상 연도는 2026년으로 고정한다.



## DB 밖에서 준비할 것

> 업로드 파일, 파일 저장소, 외부 API, 환경 변수, 벡터 인덱스처럼 SQL만으로 준비할 수 없는 항목을 적습니다. 어디에 있는 자산을 어떤 순서로 준비하고, 완료 여부를 어떻게 확인할지도 포함합니다. 해당 사항이 없다면 없다고 적습니다.
>
> 예:
> - 공지 등록에 사용할 `회의 일정.pdf`를 시연 PC의 정해진 폴더에 둔다.
> - 메일 발송 기능을 보여준다면 테스트용 SMTP 환경 변수를 설정한다.
> - 시연 전에 첨부파일을 열고 다운로드할 수 있는지 확인한다.



## 데이터 준비 방법

> 이 부분은 DB 담당자가 작성합니다. 기능 담당자가 요청한 데이터를 기존 시딩에서 재사용할지, SQL로 추가할지, 애플리케이션을 통해 생성할지 정리합니다. 참조 관계가 있는 데이터는 고정 ID, 사번, 이메일이나 코드처럼 다시 찾을 수 있는 식별자와 생성 순서를 함께 적습니다.
>
> 예:
> - 부서와 직급은 `02-departments.sql`, `03-positions.sql`의 기존 데이터를 사용한다.
> - 직원은 부서와 직급이 생성된 뒤 `10-employees.sql`에 추가한다.
> - 다른 SQL에서 참조할 관리자는 이메일 `kim.hr@healthgate.com`으로 찾는다.
> - 첨부파일이 있는 공지는 파일 저장이 필요하므로 시연 전에 애플리케이션 화면에서 등록한다.



## 충돌하거나 달라질 수 있는 조건

> 다른 기능의 시딩과 공유하는 ID나 UNIQUE 값, 실행 날짜에 따라 달라지는 값, 로컬과 시연 환경의 차이를 적습니다. DB 초기화 뒤 별도로 반복해야 하는 작업도 이곳에 남깁니다.
>
> 예:
> - 관리자 이메일은 공통 시딩과 공유하므로 새로 INSERT하지 않는다.
> - 검진 대상 연도는 현재 연도가 아니라 시연에 사용할 2026년으로 고정한다.
> - 첨부파일 저장 경로는 로컬과 시연 서버가 다르다.
> - DB 초기화 후 첨부파일이 있는 공지를 다시 등록해야 한다.



## 확인 방법

> 데이터 준비가 끝났다고 판단할 기준을 작성합니다. 화면에서 사용할 조회 조건과 관계를 확인할 SQL, 예상 개수와 핵심 상태를 포함합니다. DB 밖의 자산은 화면이나 API에서 확인할 방법을 덧붙입니다.
>
> 예: 아래 조회 결과에서 개발팀 재직 직원은 5명이어야 하고 그중 이름이 `김`으로 시작하는 직원은 2명이어야 한다. 직원 목록 화면에서도 같은 조건으로 같은 인원이 표시되어야 한다.

```sql
SELECT COUNT(*) AS active_developer_count
FROM employees e
JOIN departments d ON d.id = e.department_id
WHERE d.name = '개발팀'
  AND e.status = 'Y';

SELECT id, name, email
FROM employees
WHERE name LIKE '김%'
ORDER BY name;
```
